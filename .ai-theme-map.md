# ZERO App — Theme & Interface Style Architecture & AI Map

**CRITICAL RULE FOR AI AGENTS & DEVELOPERS:**
Every Interface Style in ZERO has its own dedicated, isolated engine file. **DO NOT OVERLAP OR COMBINE STYLES INTO SHARED MONOLITHS.**
When editing or creating an Interface Style, read and edit ONLY the exact file dedicated to that style.

---

## 1. Interface Styles Architecture & Exact File Locations

ZERO supports two canonical top-level Interface Styles:

| Interface Style | Canonical ID | Dedicated Engine File | Aesthetics & Tokens |
|---|---|---|---|
| **Fluent Glass** | `fluent` | [`src/themes/engine-fluent.ts`](file:///c:/MY%20THINGS/zero-app/src/themes/engine-fluent.ts) | Multi-layer physical acrylic glass, `#070b14` AMOLED base, specular highlight borders, drifting ambient mesh orbs, `Segoe UI Variable`. |
| **Aetherial Focus** | `aetherial` | [`src/themes/engine-aetherial.ts`](file:///c:/MY%20THINGS/zero-app/src/themes/engine-aetherial.ts) | Deep celestial obsidian `#11131b`, atmospheric cyan field glows `#38bdf8`, radial arc geometry, aurora mint focus indicators `#4edea3`, `Plus Jakarta Sans` & `Inter`. |

### Zero Style Overlap Guarantee (Isolated DOM Injection)
- **Active Engine Ingestion**: Only the active style engine's CSS is mounted into `<style id="zero-active-theme-engine">`.
- **Attribute Scoping**: `document.documentElement` receives `data-theme="fluent" | "aetherial"` and `data-engine="fluent" | "aetherial"`.
- **Instant Zero-Reload Switching**: Switching styles unmounts previous CSS completely and applies the new engine's rules with zero style leakage or class collision.
